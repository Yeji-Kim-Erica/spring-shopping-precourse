# spring-shopping-precourse
캠퍼스 프로그래밍 3기 - 프리코스: 쇼핑 API

## 기능 요구사항
- 온라인 쇼핑몰을 위한 간단한 HTTP API
- HTTP 요청과 응답은 JSON으로 주고 받음
- 스프링 프레임워크를 사용해 웹 애플리케이션으로 구현

### 회원
- [ ] 회원가입 기능
  - [ ] 이메일과 비밀번호를 기입해 회원가입한다.
  - [ ] 회원가입에 성공하면 인증 토큰을 발급받는다.
- [ ] 로그인 기능
  - [ ] 이메일과 비밀번호를 검증받아 로그인한다.
  - [ ] 로그인에 성공하면 인증 토큰을 발급받는다.

### 상품
- [ ] 상품 추가 기능
  - [ ] 이름, 가격, 이미지 URL(파일 업로드 X)을 포함한다.
  - [ ] 상품 이름 유효성 검사
    - [ ] 상품 이름은 공백을 포함하여 최대 15자까지 입력할 수 있다.
    - [ ] 상품 이름에는 아래 특수 문자만 사용할 수 있다.
      - [ ] 가능한 특수문자: (), [], +, -, &, /, _
      - [ ] 그 외 특수문자는 사용할 수 없다.
    - [ ] 상품 이름은 비속어를 포함할 수 없다.
      - [ ] [PurgoMalum](https://www.purgomalum.com/) API를 호출해 비속어 포함 여부를 검사한다.
- [ ] 상품 조회 기능
  - [ ] 상품 id가 제공될 경우 특정 상품의 정보를 조회한다.
  - [ ] 상품 id가 제공되지 않을 경우 모든 상품의 목록을 조회한다.
- [ ] 상품 수정 기능
  - [ ] 상품 id로 조회되는 기존 상품의 정보를 수정한다.
  - [ ] 상품 이름 유효성 검사를 수행한다.
- [ ] 상품 삭제 기능
  - [ ] 상품 id로 특정 상품을 삭제한다.

### 위시리스트
- [ ] 인증된 사용자가 아니라면 위시리스트 기능을 사용할 수 없다.
- [ ] 위시리스트 상품 목록 조회 기능
- [ ] 위시리스트 상품 추가 기능
- [ ] 위시리스트 상품 삭제 기능

## 구현 전략
- README에는 기능의 행동 규칙을, API 명세에는 요청·응답 형식과 상태 코드를 기록한다.
- 전체 기능의 계층을 한꺼번에 구현하지 않고, 아래 과정을 기능 하나마다 반복한다.

### 기능별 구현 흐름
1. 구현할 기능의 요구사항을 확인하고, 해당 기능에 필요한 미결정 정책을 정해 기록한다.
2. 해당 기능의 API 명세를 성공·실패 조건과 함께 작성하거나 보완한다.
3. 요구사항을 바탕으로 필요한 도메인 구조를 설계하고, 클래스별 책임과 요구사항을 정리한다.
4. 정리한 요구사항을 기준으로 AI로 테스트 코드를 작성하고 검수한다.
5. 테스트를 실행해 구현하려는 동작이 없어 실패하는지 확인한다.
6. 검수한 테스트를 바탕으로 AI로 프로덕션 코드를 작성한다. 기능 안에서는 도메인 -> 서비스/레포지토리 -> 컨트롤러 순서로 진행한다.
7. 프로덕션 코드를 검수하고, 테스트를 실행해 통과하는지 확인한다.
8. 필요한 리팩터링을 수행하고 관련 테스트를 다시 실행한다.
9. 기능 목록의 완료 상태와 AI 활용 기록을 갱신하고, 기능 단위로 커밋한다.

### 테스트 코드 작성 지침
- JUnit과 AssertJ로 기능 목록의 동작을 검증한다.
- 단위 테스트는 해당 객체가 보장해야 하는 책임에 집중한다.
- 동일한 검증 규칙을 클래스마다 불필요하게 반복하지 않는다. 다만 API 테스트에서는 검증 실패가 오류 응답으로 연결되는지 등 계층 간 연결을 확인한다.
- 정상 케이스, 예외 케이스, 경계값을 테스트한다.
- 라이브러리 자체의 동작은 테스트하지 않는다.

### 프로덕션 코드 작성 지침
- Google Java Style Guide를 기본으로 하되, 들여쓰기는 4칸으로 한다.
- 중첩 깊이는 최대 2단계까지만 허용한다.
- 메서드의 길이가 15줄을 넘어가지 않도록 구현한다.
- 메서드가 한 가지 일만 하도록 작성한다.
- else 또는 switch문을 사용하지 않는다.
- 3항 연산자를 사용하지 않는다.
- AI가 생성한 코드는 동작과 설계 의도를 이해한 뒤 반영한다.
